# Demo playbook (presenter's crib sheet)

Run-of-show for the live session. Each step is a prompt to type into Claude
Code in the **live** repo. Claude there will pull the matching step from
`docs/BUILD_LOG.md` in this repo and port it.

## Before the session
- Start a Claude Code session on `underwriting-desktop-live` **with
  `underwriting-desktop` also attached** (both repos selected), so it can
  read this reference.
- Have the finished reference app running in another tab as the
  fallback if anything goes sideways.

## Steps
| # | Prompt to type | What they'll see |
|---|----------------|------------------|
| 01 | "Scaffold the monorepo from the plan: Next.js web app, FastAPI rating and ingestion services, one Postgres with customer/policy/rating DBs, docker compose, and a status page that health-checks everything." | Four services come up; status page shows all green |
| 02 | "Generate ~8 realistic contractors GL submissions in mixed formats (fillable ACORD-style PDFs, a flattened PDF, broker emails, a questionnaire, a Word app, loss runs) with ground-truth JSON for each." | A folder of broker-style documents that look real |
| 03 | "Build the rating service: versioned rate tables (class base rates, territory, limits, deductible, residential, subcontracting, height, schedule mod bounds, fees, surplus lines tax), POST /rate returning a step-by-step worksheet, log every call, with tests." | Tests pass; Swagger at :8001/docs rates a risk and shows the worksheet |
| 04 | "Add a rate-table admin UI to the rating service at /admin: copy the active version into a draft, edit values one rating variable at a time with a required reason, show what changed vs the base version, audit every change with before/after, and activate the draft to make it live. Same operations in the API, with tests." | Draft 2026.2, raise Florida's territory factor with a reason, see "was 1.25", activate, audit trail shows who/what/why |
| 05 | "Build the ingestion service: POST /extract takes all documents in a submission (PDF, email with attachments, Word), classifies each, reads fillable ACORD PDFs from form fields, sends the rest to Claude with a strict JSON schema, and returns the canonical submission JSON with per-field confidence, stated vs inferred, source and snippet. Add a scorer against the ground truth." | Upload a sparse broker email in Swagger and get a rateable submission with inferred class code and cited snippets; the scorer prints 250/251 correct |
| 06 | "In the web app, build a submission inbox: upload a broker submission's documents to the ingestion service and store them, then an intake review page that shows each field's confidence, stated/inferred badge and source snippet, highlights what needs attention, lets the underwriter correct fields with an audited before/after, and accept the intake once the rating fields are present." | Upload the sparse email, see flagged inferred fields with snippets, fix the FEIN, accept; the history shows the correction |
| 07 | "Add an underwriting workbench for accepted submissions: editable rating inputs seeded from the submission, schedule credits/debits by category with required written reasons, Save & rate through the rating service showing the premium worksheet, and deterministic referral rules (large open claim, loss frequency, uninsured subs, NY, height, roofing, authority limits) that must be cleared with a note before it's ready to quote. Audit everything." | Roofing risk lights up four referrals; a +18% schedule trips the authority rule; a manager clears one with a note; a clean risk shows "Ready to quote" |
| 08 | "When a worksheet is ready to quote, issue a quote: confirm dates and subjectivities (suggested from the file's warnings), re-rate through the rating API pinned to the rate version shown, save a numbered, versioned quote in the policy DB that supersedes earlier versions, and generate and store a one-page quote PDF. Add a Quotes list." | Click Issue quote and open a clean quote PDF; change the deductible, issue v2, and see v1 superseded in /quotes |
| 09 | "Let the underwriter bind the latest issued quote: tick subjectivities already received (the rest stay open, due in 30 days), refuse superseded or expired quotes, create the policy on the quoted terms with policy and binder numbers, and generate and store a one-page binder and a policy document with declarations and conditions. Add a Policies list." | Tick two subjectivities, click Bind, and open the binder (OPEN items with due dates) and the policy declarations |
| 10 | "Add header search across insureds, submissions, quotes and policies in both databases (exact references jump straight to the record), a Customers list and customer page with their whole book, and detail pages for quotes (terms, rating worksheet, internal underwriting basis, versions) and policies (coverage, subjectivity status, documents), all cross-linked." | Search a broker name, open the customer, click through to the bound quote's worksheet and the policy's open subjectivities |
| 11 | "Build one audit timeline across services: UW Desktop events, rate-table changes and rating calls (from the rating service API), with filters, events from one click grouped, before → after per field, and a case view for one submission linked from its pages." | Open a case history and walk from the upload through corrections, Save & rate (grouped with the engine call), referral clearances, quote versions and binding; filter to the rate-table change |
| 12 | "Make it deployable to Fly.io: fly.toml per service, one Managed Postgres cluster with the three databases attached as secrets, rating and ingestion private on Flycast with no public IPs, web public behind a password gate with the rate admin proxied through it, non-root containers, and an idempotent deploy script." | Run the script; open the public URL, sign in, and show that rating has only a private address |
| 13 | "Add an inbox to the Submissions page: list the submission folders in the broker drop folder (samples/submissions locally, baked into the image on Fly) that haven't been extracted yet, with their documents, and an Extract button that runs the same extraction as an upload and opens intake review. A picked-up folder leaves the inbox and can't be picked up twice. Also add 10 more sample submissions, unique but in the same mix of formats." | /submissions shows "Inbox · 18 new". Click Extract on Mile High Electric (Word app): about 25 s later the review page opens with every field filled and Claude's notes. Back on /submissions the inbox shows 17 and SUB-0001 is in Received. |
| 14 | "On the Submissions page, show a live, verbose activity stream while a submission is extracted, for demos: every step, each field as it is read (form fields vs Claude, with confidence), loss rows, Claude's reasoning summary while it thinks, then open intake review." | Click Extract on Evergreen Summit Roofing: a dark activity panel opens with the timer running; 18 form fields and 3 losses appear at +0.1s, "Claude is reading the documents…", Claude's reasoning in italics, its 15 fields streaming in one by one, "Saved as SUB-…", then intake review opens |
| 15 | "Turn the landing page into the signed-in underwriter's desk: their book of business (in-force premium, loss ratio, premium by class), a prioritized list of what to do next (intakes to review, worksheets to rate or clear referrals on, quotes to issue or chase, open subjectivities, renewals to start or finish, new inbox items), upcoming renewals for the next 120 days with loss history, their recent activity, and system status. Seed each underwriter's existing book from a prior system so renewals are realistic." | Sign in as underwriter4: $998K in force, 4 renewals in 90 days; "Next up" leads with two in-progress renewals expiring in 5 and 9 days. Extract and rate a submission and watch its task advance: Review intake → Rate → Issue quote → Chase bind order |
| 16 | "Build the renewal workflow: click a policy up for renewal to see its current details, adjust and re-rate on the workbench, a comparison page of expiring vs renewing terms and rates with a re-rate button that returns to the rating page, a renewal quote issued from the comparison page together with a memo to the customer explaining the premium change, rating variable changes and rate factor changes, and every document on the policy overview page. The prior-system book needs rating inputs priced by the engine so expiring premiums can be reproduced." | Start a renewal from the desk, change terms, see the premium bridge split terms vs rates, issue the quote (it lands on Expiring vs renewing) and open the memo; issue a revised quote from there and land on Quotes with it highlighted; a Florida renewal shows the 2026.2 territory change explained |
| 17 | "Add an Accounting page: a premium sub-ledger of what each bind booked to the general ledger (full premium at bind; no cash or earning yet), as balanced journals by GL account with the policy details for audit, grouped by accounting month and filterable by the usual accounting periods, each journal linking to the UW action that booked it, and a button that pushes the shown lines to the GL as Excel or CSV and marks them as pushed." | Open Accounting, bind a policy and see its journal appear unpushed, click UW action to land on the bind's audit events, export Excel and see the batch stamped |
| 18 | "In addition to the existing formats: an API that lets other apps request GL data with the expected parameters (timeframes etc.), authorized with the user ids and passwords we set up (not how production would do it), where clicking the button shows the API documentation and a valid call returns valid JSON; and an MCP server that lets an agent interact with the app and receive valid data, where the MCP button shows the MCP spec and the server is operational for the demo." | Accounting → **API**: Try GET /api/gl (JSON with `authenticated_as`), Try it on postings, then `curl -u underwriter1 …/api/gl/summary?period=this_month`. Accounting → **MCP**: the live session shows the handshake and a `gl_summary` call; call `gl_journal` from the form; `claude mcp add --transport http uwdesk-gl …/api/mcp --header "Authorization: Basic …"` and ask Claude Code how much premium was written this month |
